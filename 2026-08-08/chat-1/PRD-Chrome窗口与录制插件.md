# 产品文档（PRD）：Chrome 窗口管理与页面录制插件

| 项目名称 | Uncle3 |
| --- | --- |
| 产品类型 | Chrome 浏览器扩展（Manifest V3） |
| 文档版本 | v0.2 |
| 文档状态 | 核心需求已确认 |
| 目标平台 | Chrome / Edge（Chromium 116+） |

---

## 1. 背景与目标

### 1.1 背景

开发者、设计师、前端测试在的日常工作中经常有两类高频需求：

1. **模拟不同设备/分辨率的窗口尺寸**：验证页面在不同窗口大小下的响应式布局表现。目前只能通过开发者工具手动输入尺寸，或者拖动窗口目测，效率低且不精确。
2. **录制页面演示 / Bug 复现视频**：录制当前页面的操作过程并分享给同事或客户。目前依赖系统录屏软件（录制范围过大、包含无关内容）或第三方在线工具（有水印、隐私顾虑）。

### 1.2 产品目标

提供一个轻量级 Chrome 插件，通过点击插件图标弹出的面板即可完成：

- **一键将当前浏览器窗口调整为预设或自定义的像素尺寸**；
- **录制当前标签页内容并导出为 MP4 视频文件**。

### 1.3 非目标（本期不做）

- 不录制麦克风 / 摄像头画面（仅录制标签页内容 + 标签页声音）；
- 不做视频剪辑（裁剪、拼接、加字幕）；
- 不做云端存储与分享链接；
- 不做移动端模拟器级别的 DPR / UA 模拟（仅调整真实窗口像素尺寸）；
- 不做多标签页同时录制。

## 3. 功能需求

### 3.1 功能一：窗口尺寸调整（Window Resize）

#### 3.1.1 功能描述

用户打开插件弹窗后，可以：

1. 从**预设尺寸列表**中选择一个尺寸，点击后**立即**将当前浏览器窗口调整为该像素尺寸；
2. 输入**自定义宽度 × 高度**（单位：像素），点击「应用」调整窗口尺寸；
3. 将当前使用的尺寸**保存为自定义预设**，方便下次复用；
4. 查看**当前窗口的实际尺寸**（实时回显，便于确认）。

#### 3.1.2 预设尺寸（默认）

| 名称 | 宽 × 高（窗口像素） | 说明 |
| --- | --- | --- |
| iPhone 14 Pro | 393 × 852 | 主流手机 |
| iPad Mini | 768 × 1024 | 平板竖屏 |
| HD | 1280 × 720 | 视频录制常用 |
| Full HD | 1920 × 1080 | 桌面大屏 |

> 说明：预设值为**浏览器窗口外框尺寸**（含工具栏/标签栏），实际页面可视区域（viewport）会小于该值。文档与 UI 中需明确标注，避免用户误解。若后续需要"按 viewport 精确设置"，见 5.3 技术方案对比。

#### 3.1.3 交互规则

- 点击预设项 → 立即调整，弹窗顶部 toast 提示「已调整为 1280 × 720」；
- 自定义输入校验：
  - 仅允许整数，范围：宽 200–7680，高 200–4320（超出范围给出内联错误提示）；
  - 宽或高为空时禁用「应用」按钮；
- 预设项支持长按/右键 → 「删除」（仅自定义预设可删，内置预设不可删）；
- 当前尺寸回显：进入弹窗时读取并展示；窗口尺寸变化后 300ms 内刷新显示；
- 支持「恢复上次尺寸」：记住每次调整前的尺寸，提供一键还原入口。

#### 3.1.4 边界与异常

| 情况 | 处理 |
| --- | --- |
| 目标尺寸超过屏幕可用区域 | Chrome 会自动钳制（clamp）到屏幕范围内；插件在调整后读取实际尺寸回显，若与目标不一致则提示「已调整至屏幕可容纳的最大尺寸」 |
| 当前为全屏模式 | 退出全屏后再调整（或提示用户先退出全屏） |
| 弹窗打开导致焦点变化 | 调整的是弹窗所属的当前窗口，不受影响 |

### 3.2 功能二：页面录制并导出 MP4（Tab Recording）

#### 3.2.1 功能描述

用户可以录制**当前标签页**的画面与声音，停止后导出为 **MP4** 文件并触发下载。

#### 3.2.2 录制流程（核心路径）

```
[打开插件弹窗] → 点击「开始录制」
    → （浏览器弹出授权框）用户允许录制该标签页
    → 录制中：弹窗显示录制时长计时、红点闪烁、暂停/继续、停止按钮
    → 点击「停止」
    → 生成视频（显示「正在生成 MP4…」进度）
    → 自动触发 MP4 文件下载，文件名：{页面标题}_{yyyyMMdd_HHmmss}.mp4
```

#### 3.2.3 详细需求

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| R-01 | 仅录制当前标签页 | 使用 Chrome 标签页捕获能力，不包含其他窗口/桌面内容 |
| R-02 | 录制标签页声音 | 默认开启录制标签页音频；提供开关（录制前设置） |
| R-03 | 录制中状态保持 | 录制中弹窗可关闭，录制不中断；工具栏图标显示「录制中」徽标（红色圆点/计时） |
| R-04 | 暂停 / 继续 | 支持录制中途暂停与恢复，暂停时计时停止 |
| R-05 | 停止与导出 | 停止后自动完成编码并下载 MP4；无需用户二次操作 |
| R-06 | 录制时长提示 | 实时显示已录制时长（HH:MM:SS） |
| R-07 | 录制上限保护 | 单次录制最长 10 分钟，到达上限自动停止并提示（防止内存溢出） |
| R-08 | 丢弃录制 | 停止后可选择「丢弃」，不生成文件（实现调整：见第 11 节 D-01） |

#### 3.2.4 输出规格

| 项目 | 规格 |
| --- | --- |
| 容器格式 | MP4（H.264 视频编码，用户侧兼容性最好） |
| 分辨率 | 与标签页实际渲染分辨率一致 |
| 帧率 | 目标 30fps（取决于系统性能） |
| 文件命名 | `{页面标题}_{yyyyMMdd_HHmmss}.mp4`，标题做文件名安全字符过滤，超长截断至 50 字符 |
| 下载方式 | 触发浏览器默认下载（进入默认下载目录），并通过下载 API 记录 |

#### 3.2.5 边界与异常

| 情况 | 处理 |
| --- | --- |
| 用户拒绝录制授权 | 提示「需要授权才能录制当前页面」，可重试 |
| chrome://、扩展页、Chrome Web Store 等受限页面 | 这些页面无法被捕获；检测到后禁用录制按钮并给出原因说明 |
| 录制中刷新/关闭标签页 | 录制自动终止；已录内容尽量导出（若可行），否则提示录制已中断 |
| 录制中切换标签页 | 录制内容仍以原标签页为准（标签页捕获特性），UI 上给予文案提示 |
| 编码失败 | 提示失败原因，提供「导出 WebM 原始文件」的降级入口 |

### 3.3 通用功能

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| G-01 | 插件弹窗 UI | 单页集成布局，无 Tab 切换；上方「窗口尺寸」区，下方「页面录制」区，分隔线隔开 |
| G-02 | 设置项 | 自定义预设管理、录制音频开关、录制时长上限，存储在本地（chrome.storage.local） |

| G-05 | 多语言 | 首期仅中文文案，文案集中管理预留英文扩展 |

## 5. 技术方案概要（供开发评估）

> 本节仅为技术选型预研，最终方案以开发阶段验证为准。

### 5.1 总体架构

- Manifest V3 扩展：`popup`（弹窗 UI）+ `background`（Service Worker，负责录制会话管理与下载）+ 必要权限声明。
- 权限：`windows`、`tabs`、`tabCapture`、`downloads`、`storage`、`offscreen`。

### 5.2 窗口尺寸调整

- 调用 `chrome.windows.update(windowId, { width, height })`；
- 通过 `chrome.windows.getCurrent()` 回显实际尺寸；
- 注意：设置的是**窗口外框尺寸**；`chrome.windows.update` 对部分平台/窗口状态（如最大化）的行为需在开发阶段逐一验证。

### 5.3 录制与 MP4 导出（关键难点）

Chrome 录制链路：`chrome.tabCapture.getMediaStreamId()` → `getUserMedia` 获得媒体流 → `MediaRecorder` 录制。存在两个关键约束：

1. **授权手势约束**：tabCapture 必须在用户手势上下文中发起，需在弹窗点击时立即获取 streamId 并传入录制上下文；
2. **格式约束**：`MediaRecorder` 原生输出通常为 **WebM（VP8/VP9/AV1）**，MP4 需要额外处理。

候选方案对比：

| 方案 | 描述 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- | --- |
| A. MediaRecorder 直出 MP4 | 指定 `mimeType: video/mp4` | 零转码成本 | 各 Chrome 版本/平台支持不一致，兼容性不可控 | 作为运行时探测的优先尝试 |
| B. Offscreen Document + ffmpeg.wasm 转码 | WebM → MP4（H.264） | 兼容性最好，全平台一致 | ffmpeg.wasm 体积大（约 30MB），转码耗时约为视频时长 0.5–1 倍，大文件内存压力 | **主方案（兜底保证）** |
| C. 录制 WebM 直接交付 | 不做 MP4 | 最简单 | 与需求冲突，Windows 兼容性一般 | 仅作为失败降级 |

**推荐策略**：运行时先探测方案 A 是否可用（`MediaRecorder.isTypeSupported('video/mp4')`），可用则直出；不可用则走方案 B 用 Offscreen Document + ffmpeg.wasm 转码；两者都失败时降级为 WebM 下载并提示。

### 5.4 录制生命周期

- 录制会话由 background Service Worker 统一管理（MV3 下 Service Worker 有休眠风险，长任务置于 Offscreen Document 中执行，保持录制稳定）；
- 状态机：`idle → requesting → recording → paused → encoding → done / discarded / error`；
- 弹窗与 background 通过 `chrome.runtime.sendMessage` / Port 同步状态与计时。

## 7. 验收标准（关键用例）

### 7.1 窗口尺寸

1. 点击「HD」预设后，当前窗口外框尺寸变为 1280 × 720（允许因屏幕限制被钳制并有提示）；
2. 输入 99999 × 800 点击应用，出现范围校验错误，窗口不变；
3. 保存自定义预设 800 × 600 后，列表中可见该项，点击生效；重启浏览器后预设仍存在；
4. 「恢复上次尺寸」能将窗口还原为调整前的尺寸。

### 7.2 页面录制

1. 在普通 https 页面点击开始录制，授权后计时开始，图标出现录制徽标；
2. 录制过程中关闭弹窗，录制不中断；重新打开弹窗可看到计时继续；
3. 暂停 5 秒后继续，最终视频时长不包含暂停时间；
4. 停止后自动下载 MP4，文件可用系统播放器正常播放，有声音（若开启音频录制）；
5. 录制 10 分钟自动停止并正常导出；
6. chrome://settings 页面录制按钮禁用且有原因说明；
7. 用户拒绝授权时，给出提示且可重试，不崩溃。

## 11. 实现决策与偏差记录（2026-08-08，v1.0.0 交付）

| 编号 | 决策 / 偏差 | 说明 |
| --- | --- | --- |
